Confirmed override
ARK-5's VSH virtual_pbp.c explicitly chooses the PBOOT load-exec path when
an installed update exists and otherwise selects the ISO's EBOOT.BIN.
This, together with the supplied update and observed hardware differences,
confirms the update can bypass the native executable changes in the ISO.
It does not yet identify the exact cause of the shutdown without that update.

New, narrow difference to test
The original ISO and every earlier candidate retain PARAM.SFO HRKGMP_VER=19.
The supplied working update's PARAM.SFO omits HRKGMP_VER.
ARK-5 reads HRKGMP_VER into opnssmp_type and passes a nonzero value into
SceGameInfo.opnssmp_ver. The firmware init reconstruction loads the extra
flash2:/opnssmp.bin module when this field is nonzero; that module is part of
the EBOOT-decryption path. PPSSPP's ordinary HLE boot does not reproduce that
real firmware path. The ISO still contains its original SYSDIR/OPNSSMP.BIN.

0.2.51 clears the 32-bit HRKGMP_VER setting from 19 to 0. Only one byte
actually differs in the 560-byte PARAM.SFO (offset 408). Its other fields,
including game ID and localized title, are exact. No firmware files are
modified. The original OPNSSMP.BIN inside the ISO is preserved.
This tests whether the stale decryption request causes or contributes to
the shutdown. It is not a proven fix and does not rule out another loader,
memory-layout or native-code issue.

Test procedure
Apply ONE matching local test patch. For the newest failed ISO, use the
0.2.50-to-0.2.51 upgrade. Keep the old ISO and PBOOT.PBP backup. Temporarily
disable only PSP/GAME/UCJS10117/PBOOT.PBP. Fully restart the PSP (not sleep)
before launching the separate, newly named 0.2.51 ISO, so cached launcher
metadata or an earlier game's decryption flag cannot carry over into this test.
Check startup/title version and home-menu spacing. If it shuts down again,
restore PBOOT.PBP. Do not change firmware or delete saves for this test.
